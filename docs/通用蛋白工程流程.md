# EvoMax-Enhanced：抗体与酶的通用改造流程

## 1. 平台定位

项目现在按“固定骨架、限定可变区域、多个模型通道、实验回流”的方式设计。抗体和酶共用评分与审计框架，但输入约束和结构筛选指标分别配置，不把抗体的 CDR 规则套用到酶上。

## 2. 统一流程

```text
私有 WT 序列/结构/可变区域
              ↓
候选生成（单点、组合或 ProteinMPNN）
              ↓
ESM-2 全局序列合理性
              ↓
ESM-C 长上下文序列复核
              ↓
ESM-IF1 结构条件兼容性
              ↓
ProteinMPNN 结构条件设计/可行性过滤
              ↓
RF3 或 OpenDDE 结构与界面/复合物复核
              ↓
tFold 或同类结构验证
              ↓
实验测定 → GPR校准 → 下一轮设计
```

## 3. 抗体模式

- 固定重链/轻链骨架，只允许指定 CDR 或经过论证的框架位点变化；
- 先用 ESM-2 和 ESM-C 处理序列候选；
- 用 ESM-IF1 和 ProteinMPNN 检查结构条件下的可行性；
- RF3/OpenDDE/tFold 作为结构、复合物和界面复核，不直接等同于亲和力；
- 保留 WT、单突变、组合突变和模型对照，进入 ELISA、BLI 或 SPR。

## 4. 酶改造模式

酶的目标通常不是结合亲和力，而是活性、热稳定性、底物谱、表达量或选择性。因此每个项目必须先定义 assay 标签和可变区域：

- 催化残基和必需配位残基默认固定；
- 活性口袋、底物通道、界面或远端变构位点可作为候选区域，但需有结构或实验依据；
- ESM-2/ESM-C 评估序列合理性，ESM-IF1/ProteinMPNN 评估折叠和局部结构兼容性；
- RF3/OpenDDE/tFold 评估整体结构、复合物或底物相关构象；
- GPR 的标签应按具体 assay 建模，不能把抗体的结合信号和酶活性混在一个模型里。

## 5. 各模块如何体现增强

| 模块 | 平台作用 | 不能直接声称 |
|---|---|---|
| ESM-2 | 快速全序列突变筛选 | 实验活性/亲和力提升 |
| ESM-C | 更强的长上下文序列复核 | 未校准的绝对性能预测 |
| ESM-IF1 | 结构条件序列兼容性 | 直接预测结合常数或催化速率 |
| ProteinMPNN | 结构条件生成、固定区域设计和可行性过滤 | 单独证明功能提升 |
| RF3/OpenDDE/tFold | 结构、复合物和界面复核 | 高置信结构等于高功能 |
| GPR | 用本项目实验数据校准功能排序 | 没有实验标签时的伪预测 |

## 6. 阶段门槛

1. 输入序列、结构链和可变区域逐残基一致；
2. 所有模型权重、版本、参数和设备被记录；
3. ProteinMPNN 输出 FASTA 非空、序列 ID 唯一、只改变允许区域；
4. RF3/OpenDDE/tFold 输入非空，结构和界面指标分开报告；
5. 实验标签按项目分层，使用独立留出集评估 GPR；
6. GitHub 只放通用代码和脱敏模板，序列、结构、候选库和结果保留在私有服务器。
